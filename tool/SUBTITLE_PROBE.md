Subtitle script detection
=========================

The bitrate result appears first. A separate bounded worker updates the subtitle
label, using HLS subtitle-track labels/text, MP4 subtitle tracks, or local OCR of
the bottom 32% of sampled frames. Generic `zh`/`zho` language tags and the title of
the anime do not determine the script. Insufficient evidence stays unknown.
Two selectable subtitle tracks are labelled separately from mixed-script text.

The Windows build includes `kazumi_subtitle_ocr.exe`, which uses the installed
Windows Chinese OCR engine. Video frame extraction uses FFmpeg/FFprobe from PATH
(or `tools/` beside Kazumi). Missing tools/languages result in an unknown label.
Other platforms currently support HLS text/metadata detection only.
No cloud OCR is used. Temporary samples/frames are removed after each probe.

HLS reuses at most 12 MiB and three already downloaded media segments per source.
Encrypted AES-128 segments fetch only their keys; fragmented MP4 fetches its init
data. HLS and MP4 retain up to 16 frames per window, adjusting the interval to
include short HLS segments. Four distributed frames are checked first, followed
by the intervening frames only on insufficient evidence. The original image is tried first; insufficient evidence
triggers pink/white color separation and grayscale alternatives. Evidence from
different transformations is assessed separately, with unchanged thresholds.
Only on failure, HLS fetches up to eight additional segments (6 MiB each,
one at a time). MP4 keeps the original 40%, 25%, 55% windows, then expands to
70%, 15%, 85%, 33%, 62%. HLS uses the same fractions, excludes already retained
segments and deduplicates positions. Blank original windows do not stop expansion.
MP4 extraction retains 16 frames over the same eight-second window. OCR first
reads four distributed frames, then inspects the intervening frames only when
needed, catching brief captions without another network seek. Early recognition
stops further work. At most two probes run concurrently.
MP4 needs additional range requests for subtitles/frames. Each probe has a 45s
deadline after acquiring a worker. Closing/restarting the panel cancels work.
Labels describe the sampled episode, not all episodes of the season.
Unknown results show whether text was insufficient, no text was read, video
decoding failed, tools/languages were missing, or the work timed out. Partial
sampling failures are shown with safe error summaries, without media URLs.

Verification (PowerShell 7)
---------------------------

After `flutter build windows --release`, run:

```powershell
python tool/generate_subtitle_fixtures.py
$env:KAZUMI_SUBTITLE_OCR_EXE = (Resolve-Path 'build/windows/x64/runner/Release/kazumi_subtitle_ocr.exe').Path
flutter test test/subtitle_script_probe_windows_test.dart
```

The generator requires Pillow, cryptography and FFmpeg. The opt-in tests exercise
real frame extraction, simplified/traditional OCR, outlined bilingual subtitles
in sub-second segments, non-subtitle Chinese text, blank/corrupt frames,
conditional HLS/MP4 fallback, brief captions between sparse frames, expansion
after all original windows/two HLS fallbacks are blank, early stopping,
implicit-IV AES-128, fMP4 init segments and MP4
text subtitles.
Regular tests exercise parsing, evidence thresholds, persistence, memory bounds,
concurrency, cancellation and timeout without native dependencies.

`subtitle_characters.dart` is generated by `tool/generate_subtitle_characters.py`
using OpenCC 1.2.0. Derived character data is attributed to OpenCC under Apache-2.0;
see `licenses/opencc.txt`.
